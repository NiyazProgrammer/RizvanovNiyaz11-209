# Deployment / запуск краулера (Deployment Man)

Краткая инструкция для того, кто **первый раз разворачивает** проект или **проверяет сдачу** без чтения исходников.

## Что должно быть на машине

| Требование | Проверка |
|------------|----------|
| Python 3.10+ (желательно 3.11+) | `python3 --version` |
| Сеть (доступ к `https://habr.com`) | браузер или `curl -I https://habr.com` |

## Установка и запуск (с нуля)

```bash
cd /path/to/RizvanovNiyaz11-209
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python crawl.py
```

Ожидаемое поведение:

1. В консоли — фаза 1 (счётчик уникальных статей по каждой seed-странице), затем фаза 2 (`downloaded 10/100` … `100/100`).
2. Код выхода `0`. При нехватке URL — сообщение `ERROR: only N...` и код `1`.

**Время:** порядка нескольких минут из‑за пауз между запросами (~0.5–1.5 с на запрос; сотни HTTP-запросов).

## Где лежит результат

| Артефакт | Назначение |
|----------|------------|
| `corpus/001.txt` … `corpus/100.txt` | Сырой HTML страниц статей (разметка не удаляется). |
| `index.txt` | Соответствие: `номер<TAB>полный_URL` (UTF-8). |
| `seed_urls.txt` | Список URL лент, с которых собирались ссылки на статьи. |

## Токенизация и лемматизация (офлайн, без сети)

После появления `corpus/*.txt`:

```bash
source .venv/bin/activate
pip install -r requirements.txt
python tokenize_lemmatize.py
```

| Артефакт | Назначение |
|----------|------------|
| `tokens.txt` | Уникальные токены: одна строка — один токен (`\n` в конце каждой строки). |
| `lemmas.txt` | Группы: `лемма` + пробел + все поверхностные формы через пробел. |
| `ru_stopwords.txt` | Союзы, предлоги и др. стоп-слова (можно расширять). |

Проверка формата:

```bash
python tokenize_lemmatize.py   # пересоздаёт оба файла
wc -l tokens.txt lemmas.txt
sort tokens.txt | uniq -d | wc -l   # ожидается 0 — нет дубликатов
head -n 3 tokens.txt
head -n 2 lemmas.txt
```

## Инвертированный индекс и булев поиск

Требуется `corpus/*.txt` и установленные зависимости.

```bash
python boolean_search.py build
python boolean_search.py -q "python AND код"
python boolean_search.py   # режим query> … до пустой строки / quit
```

| Артефакт | Назначение |
|----------|------------|
| `inverted_index.json` | `postings`: термин (лемма) → список номеров документов; `doc_ids` — универсум для `NOT`. |
| `boolean_search.py` | Сборка индекса (`build`), разбор запроса из строки (`-q` или stdin). |

Формат запроса: термины (буквы кириллица/латиница, как в индексе), операторы **AND**, **OR**, **NOT**, скобки. Пример: `(слово1 AND слово2) OR слово3 OR NOT слово4`.

Приоритеты: **NOT** > **AND** > **OR**.

## TF-IDF по документам

Цепочка: `corpus/*.txt` → `python tokenize_lemmatize.py` → `python tfidf_export.py`.

```bash
python tokenize_lemmatize.py
python tfidf_export.py
# компактные файлы (только tf>0 в документе):
python tfidf_export.py --sparse
```

| Артефакт | Назначение |
|----------|------------|
| `tfidf_terms/NNN.txt` | По строке из `tokens.txt`: `термин idf tf-idf` (10 знаков после запятой). |
| `tfidf_lemmas/NNN.txt` | По строке из `lemmas.txt`: `лемма idf tf-idf`. |

**Формулы:** \(|d|\) — сумма частот отфильтрованных токенов; tf термина = count/|d|; tf леммы = сумма count по формам из строки `lemmas.txt` / |d|; idf = ln(1 + (N+1)/(df+1)); tf-idf = tf×idf.

По умолчанию в каждом файле столько строк, сколько терминов/лемм в словаре (полный вектор; нули у tf-idf допустимы). Каталоги `tfidf_terms/` и `tfidf_lemmas/` в `.gitignore` — для сдачи сгенерировать локально или `git add -f`.

Проверка:

```bash
wc -l tfidf_terms/001.txt tfidf_lemmas/001.txt
head -n 3 tfidf_terms/001.txt
grep '^python ' tfidf_terms/001.txt tfidf_terms/002.txt   # idf у python совпадает
```

## Проверка без запуска кода

Преподаватель может убедиться в выполнении задания, открыв файлы в репозитории:

1. **`index.txt`** — должно быть **не менее 100** строк; каждая начинается с числа и табуляции, далее URL `https://habr.com/ru/...`.
2. **`corpus/001.txt`** (и несколько других) — в начале файла виден HTML (`<!DOCTYPE` или `<html`), текст на русском (`lang="ru"` в типичном случае).
3. Сопоставление: строка `N` в `index.txt` соответствует файлу `corpus/NNN.txt`, где `NNN` — номер с ведущими нулями (например, `1` → `001.txt`).

Команды для быстрой проверки в терминале (опционально):

```bash
wc -l index.txt          # ожидается 100
ls corpus | wc -l        # ожидается 100
head -n 3 index.txt
head -n 5 corpus/001.txt
```

## Конфигурация

- Минимальное число статей: константа `MIN_ARTICLES` в `crawl.py` (по умолчанию 100).
- Список лент: только `seed_urls.txt` (можно добавить строки `https://habr.com/ru/articles/pageN/`, если уникальных статей не хватает).

## Соответствие robots.txt

Краулер делает умеренное число запросов с задержками и идентифицируемым `User-Agent`. Перед промышленным использованием имеет смысл свериться с актуальным `https://habr.com/robots.txt`.
